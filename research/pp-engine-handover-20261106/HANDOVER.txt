POTENTIALLY USEFUL IDEAS
- Native D/G-consistent pressure projection, conservative momentum flux/full
  constant-viscosity stress, SSPRK3 stage acceptance and CFL/positivity checks.
- FineReceiver captures only where a segment intersects genuine native text
  occupancy and the first creation front. It integrates hazard along the accepted
  segment, preserves identity/mass and records the actual pixel/event fraction.
- One continuous physical epoch, explicit observation versus accepted fixed-tick
  time, native ownership/pixel/colour bookkeeping, transactional rejection and
  complete snapshots. Captured solids are not displayed as frozen gas particles.
  Re-emission uses stored lineages, not freshly rasterized replacement mass.
- StateEvents/StateControls/EventFields reuse the existing native state/segment
  primitives. Ward/C1 embeddings, immutable sparse field chunks and a small
  control descriptor avoid passing giant field plans on every frame. Identity
  fields stay unchanged. These are model/representation ideas, not SDK dictates.
- Geometry union coverage and density-weighted colour moments need separate
  treatment. Native compensated reductions preserve small positive contributions.
- A native area controller should expose a representable/raster-limited result
  rather than pretend an unreachable pixel-area tolerance converged. One q=.9
  case has adjacent representable scales whose area jump makes the 1px target
  impossible; nearest observed residual is 1.4651px. Exact linear raster area
  and exact visible contact timing are NOT proved.
- Shared allocations, input chunks/leases, compact diagnostics and explicit
  completion are engine concerns. An app inspector/capture should not force
  full state download or a global host fence every physics/render operation.

CURRENT REAL LIMITS — DO NOT PROMOTE THESE RESULTS
All browser GPU evidence here used SwiftShader. It checks finite implementation
behaviour, not genuine hardware performance. No complete initialized physics+
graphics under10ms workload has been established. Native/Vulkan f64 and browser
WebGPU f32 are distinct; no cross-backend zero-copy guarantee is established.

The internal source→capture→owner/pixel→re-emission→restore cycle passed finite
software tests. The full physical presentation is still missing integrated ports
stage coupling, native initialized-world accuracy, actual fine-support formation,
and a documented public automatic GPU factory/runtime bridge.

FluidInitial's GPU candidate FAILED its first accuracy case: state error
1.16956e-5 (limit2e-6), pressure error .001194 (limit2e-5). Later GPU cases were
not reached. Its WASM reference checks passing do not repair that failure.

The actual27 state test had no fragment-count increase/reopening in its sampled
frames and bounded area/colour results. Visible contacts precede semantic Ward
coincidences; near-linear visible connected-component timing remains unproved.
Full29-view runtime, ordinary public-SDK integration and hardware performance
remain unqualified. No new full-presentation movie was recorded or deployed.

FineFormation's areal-fill rule is a declared constitutive assumption: coverage
is derived from actual deposited mass and a declared areal density; excess mass
remains attached thickness. It is not thermodynamics, surface diffusion or an
empirically qualified optical model. Its reference contract/tests are included;
there is no independent time fade or missing-mass top-up. You may replace it.
