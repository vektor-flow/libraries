E317 selected-page successor
prepareProducerDocument(result, owner, {page, previous, tiles, resources}) binds
the complete document before projection. page is zero-based and required for
multipage input; omitted page retains one-page compatibility. Return .bound is
always the full-document provenance for the next revision. For same-revision
switching use selectProducerPage(prepared, page), which authenticates its input
and retains the full bound value. Explicit .page width/height and update
width/height describe the selected page; caller sizes its render view explicitly.
Cross-page semantic groups are unsupported and rejected, including off-page
crossings. Complete dependency groups remain with empty local off-page ranges;
IDs, versions and dependency edges remain owner-authored. Only local indices
and ranges change. Resources and tiles are selected exactly by leaf dependencies;
full-document inputs must supply every resource and glyph tile before projection.
All projected arrays/tables/payloads are independently copied. No destination
or anchor provenance, image/vector extension, GPU algorithm change or performance
claim. Existing implicit-multipage rejection remains valid and unchanged; explicit
page selection is its named successor, covered in producer-pages.mjs.
Projection scans all groups/resources plus selected leaves and copies full paint
and payload tables. Initial preparation binds/validates all leaves and resources.
Full binding is NOT guaranteed linear: existing operation/leaf find, source
lookups, UTF offset scans and previous dependency closure can be superlinear.
This change does not optimize those source-owner algorithms. Tests use synthetic
exact-schema source-only ABI fixtures, not compiled producer output, PDFs or GPU.
