REAL RECORD METADATA AND ZERO-WIDTH SEMANTICS
The actual record producer constructs Aggregate records through the existing
assign_record_field_layout; fields are identified by names, not map iteration
order. record_field_layout copies width/kind/dynamic element/shared count/channel
tag/tuple tag and rebases all descendants relative to the selected field. The new
builder730 feeds those extracted layouts to the REAL indexed_layout, which emits
prefix-sum widths and all seven ValueSlice members. Relabeling738/742 copies whole
slices with their already absolute offsets. It does not drop resource metadata or
confuse indexed prefix "1." with "10."; each lookup requires the dotted prefix.

Record canonicality is tested on a newly built selector map, so the shared-storage
equality shortcut does not conceal reconstruction differences. Root width/kind,
tuple/shared/channel/dynamic tags, selector names/offsets/widths/tags and recursive
dynamic element structure all participate in same_inference_layout. Orphans at
the record level are omitted by extraction/reconstruction and hence fail equality.
This is a record-boundary check, NOT a new general validator for arbitrary opaque
leaf layouts; unsupported leaf contents intentionally remain supplied unchanged.

The zero-width tie comparator759-762 is a strict ordering: offset first, then
empty before nonempty at the same offset; equal empties remain equivalent. That
matches packed storage: an empty field at a boundary contributes no words before
the nonempty field beginning there. Several empty fields at the same boundary
can be lexically reordered without changing any slice. An empty-only named
record similarly round-trips at width0. The projection rebuild uses current
physical field order, so an empty actual does not dictate a new counted ABI order.

Concrete actual-producer trace: metadata(empty,empty) has numbers/texts/count at
offset0, widths0/0/1. Lexical map order starts with count, but the new canonical
ordering puts the two empty fields before count and reconstructs identical slices.
If the old assignment builder subsequently adds fixed, it may move the two empty
fields to offset1 after count; that is a different but still packed layout. The
new validation accepts that actual as well, and maps by names into required order
numbers/texts/count/fixed. It does not assume the empty actual's original order.
An empty middle sibling at offset1 and the following nonempty field at offset1
are likewise retained. No repeated assign_record_field_layout calls are used
inside the new rebuild to scramble the tied fields.
