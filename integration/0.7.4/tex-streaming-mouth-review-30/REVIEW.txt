F1 — P2: virtual-EOF origin statement is false for nonempty source anchors.
Original VKF lines 89-112 trim trailing ASCII spaces into the logical CR unit's
source span. emit(), lines123-129, appends an origin whenever stop>start.
Thus raw "a " (two bytes, no newline) emits a with origin0, then a generated
space with [1,2), provenance1, origin1. Raw " " emits generated par [0,1),
provenance1, origin0. Raw "a" instead emits generated space [1,1), origin=-1.
For raw backslash at EOF, the CR unit itself has width zero but the composite
control token covers the escape [0,1), provenance1, origin0. With a trailing
space its span is [0,2). Original contract and unit() comment incorrectly make
zero-width/no-origin unconditional for virtual EOF. The correction preserves
all existing spans, origin issuance and provenance=1. These origins anchor
original bytes; they do not assert the user authored a CR/par/control spelling.
24 host adapter assertions include these nonempty and empty derived spans and
preview rejection before registry issuance. Five direct native boundary cases
cover the distinction; all native cases remain unexecuted.

F2 — P2 documentation/API: adapter does not return a context.
Original contract says to use the returned context for subsequent reads.
acceptMouthOrigin() actually returns the issued origin object, or null; it
mutates the supplied context registry only after successful checks. Corrected
contract says to reuse that same context and retain token plus issued origin.
Existing host tests and this review's actual JS checks exercise that return API.
No JS change is needed. A source consumer following the old text would try to
use an origin/null as a context, so this correction is material to integration.

Profile limits are explicit, not TeX equivalence claims
Own formatted-like ASCII categories are neither INITEX nor a complete plain or
LaTeX format. Non-ASCII lexemes/BOM and Unicode control names reject; Unicode
inside comments is transport-only. ^^ is not translated: identical category7
pairs reject conservatively, including custom superscript characters. Even
pairs for which full TeX might not translate are outside this accepted profile.
CR/LF reassignment, alternate endlinechar and ordinary category5 assignment are
unsupported. No expansion, grouping executor, conditionals, namespace meanings,
registers, include execution or initialized package state exists. Handwritten
assign calls simulate future lexical feedback, not execution of \catcode.
The actual installed first controls ifnum, NeedsTeXFormat and ProvidesPackage
remain execution blockers. Lexing their names gives no package compatibility.
