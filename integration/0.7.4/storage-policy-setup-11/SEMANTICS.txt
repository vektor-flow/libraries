No fallback exec mode or unconfined transition is used. The pre profile's
change_profile denial restricts explicit profile-change APIs, not its separately
specified exec transition. Its capability denial is deliberately replaced at
bwrap exec BEFORE NNP; the original candidate did not require NNP before bwrap.
This candidate never clears NNP and refuses inherited NNP=1. Adding NNP to the
outer service would block this design; do not clear it or weaken a service guard.
After bwrap, NNP MUST be 1 and the exact two-profile denial stack enforced.
Missing labels, complain mode, extra label components, namespace-prefixed labels,
credential drift, nonzero capability masks or malformed status stop before exec.
CapBnd may remain before bwrap but must be ZERO at post, along with CapInh/Prm/Eff/Amb.
The four real/effective/saved/fs UID/GID fields must each equal the original
nonzero identity. No payload is allowed as root, even root in a child userns.

SCOPE OF NEW SYSTEM POLICY
Dedicated binary is an unchanged copy of installed util-linux, not a renamed
unrelated whitelisted application or a shell/interpreter with setup capabilities.
Only that pathname attaches the new setup profile. Ordinary /usr/bin/unshare and
all system restriction policies remain unchanged. The setup profile permits
reads and system-library mmap, current-user ID-map/setgroups writes, inherited
charged receipt writes, and receive/readby custody access from unconfined.
The rprivate rule's rw token represents absence of MS_RDONLY in the propagation
syscall; it grants no writable bind/remount. No general mount, umount, pivot_root,
arbitrary exec, write-to-policy, or change_profile permission is granted.
The pre Python runs without capabilities and cannot create namespaces or mount;
only the already-policy-approved bwrap can be execed from that profile.

AppArmor does not authenticate argv, attempt grants or cgroup paths. These remain
controller responsibilities; the profile alone is NOT a grant or a general
host sandbox. Direct use of the copied generic unshare with other options is
outside the contract, and no unrestricted capability-bearing child can be execed
from its profile. The grant-pinned command builder selects only the exact
nonforking map-current-user/user/mount/private sequence. No --map-root-user,
--keep-caps, helper-fork options, persistent namespaces or host setup syscall.
No C helper or compiled custom executable is introduced.
