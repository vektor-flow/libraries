RAW ENCODER / PDF OBJECT REVIEW
Read actual proposed encode_core, validate, actual_text, glyph/clipped_glyph,
form/path provider, stream/object/xref serializers and text_chunks.join. This
conclusion is not inferred solely from the independent stream model.

selection_begin is captured BEFORE that cluster's optional paint command; the
wrapper is installed AFTER the final complete glyph command. Glyph helpers
produce complete q/cm/Do/Q objects; clipped glyphs complete re/W/n before Do/Q.
Only drawn kind0 leaves enter this mode. BDC/EMC therefore does not cut a glyph
command, path construction, text object, or Form object. The page q/cm and final
Q stay outside. The selected layer adds no BT/ET or font/text-showing operators.
Paint state intentionally persists across clusters; marked content does not add
graphics-state save/restore and cannot desynchronize current_paint caching.
The first wrapper may immediately follow the page's cm as cm/Span: slash is a
PDF name delimiter, so this is not a fused operator. actual_text terminates its
body with LF before EMC, which also terminates a possible trailing comment.
Reference for complete-object boundary rule: Adobe pdfmark reference,
https://opensource.adobe.com/dc-acrobat-sdk-docs/library/pdfmark/pdfmark_Basic.html
(Marked content). The large ISO PDF fetch failed; no claim to have fetched it.

text_chunks.join uses an exclusive stop, so join(commands,selection_begin,
command_count) consumes exactly the current cluster. Resetting command_count to
selection_begin+1 discards stale tail slots. Later writes overwrite those slots;
final join never consumes them. Cluster compression cannot exceed the original
2*page_leaf_count+2 allocation: each leaf produces at most paint+draw; a cluster
with no draw command contributes at most one wrapper. For a validated nonempty
leaf iteration selected_cluster is in range; after the last cluster no later leaf
reads it, including trailing empty pages. Cross-page clusters already refuse.

Form/alpha/page object allocation, one-based references, resource ordering and
bulk serializer are unchanged. Content stream Length is recomputed from actual
UTF-8 byte length. pack retains byte starts/stops; serialize sums body bytes plus
decimal ID width and15 fixed object framing bytes, matching syntax.object. Thus
ActualText size changes propagate through xref/startxref instead of reusing stale
offsets. The BOM hex helper handles supplementary pairs and does not embed raw
UTF-16 bytes into the UTF-8 PDF stream. No newly introduced malformed-object or
marked-boundary defect was found by this source inspection. This is not native
PDF parser/raster evidence or a proof for arbitrary malformed input. The inherited
font path validator restricts tokens but does not fully validate operator arity;
the reviewed path relies on accepted pinned font/operator assets, not arbitrary
caller-supplied fonts being semantically valid.

Outline ActualText alone is NOT ordinary-reader selection. Missing positioned
standard text/ToUnicode fallback, authored source/map/revision attachments and
actual Adobe/Edge interaction remain requirements, not source bugs purportedly
fixed by this patch. The current future native fixture checks string occurrences;
