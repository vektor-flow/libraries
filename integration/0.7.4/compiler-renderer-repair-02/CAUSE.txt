SOURCE-ONLY CAUSAL FINDING — NOT NATIVE CONFIRMATION

Authenticated D288 unit53 value_layout/layouts_1.cpp has two independent ways
to narrow counted primitive storage to an inline caller extent:

1. merge_inferred_layout, original lines403-538. For a counted primitive vector
   (DynamicF64List, width1) and a fixed singleton, the kind-specific cases do not
   match. The final width/selector-count comparison replaces current with the
   fixed candidate. A numeric singleton has width1 plus a selector; a String
   singleton has width2. Nine-element inputs also replace it. This happens
   recursively inside ordinary record fields, not only for top-level vectors.
2. refine_full_projection_path, original lines701-750. A complete field demand
   with different current/candidate kinds takes `else current = candidate`.
   This can narrow even a counted field to a fixed EMPTY candidate. Ordinary
   calls invoke this before refine_signature_parameter_from_argument, so
   guarding only the width-based merge would leave the defect present.

Why this is a defect: a field declared [str]/[int]/[num] accepts independently
supplied lengths. One inline caller does not establish a fixed extent for all
calls or for a counted producer. The single ordinary function signature is
shared across those calls. Specialization requires an independent proof;
slot width and one full-field use provide no such proof.

The original fixed->counted compatible_vector branch also recognizes only
numeric/complex leaves. Once a nonempty String field has become fixed, merely
merging its later counted String producer cannot repair the narrowing. This
patch prevents the wrong initial narrowing; it does not broaden that branch.

existing plain counted Numeric or String vector only when the candidate is
a canonical inline vector with exactly identical primitive element layouts.

layout or fixed-formal proof is newly accepted. Same-layout and conversion
validation remain intact. No edit to embed_numeric_return, call-stage12685,
function_lowering, allocator, typedArena or fixed-spread handling. A333 is
reopened; D267/D289 and all other exclusions remain in force. There is no
unavoidable overlap with their implementation bodies for this candidate.
